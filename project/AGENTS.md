# Cobalt dashboard project

This is the editable source for a durable dashboard. Use normal filesystem tools.

1. Read `.cobalt/context.json` for the dashboard ID and checkout version. Retain that version through import; a conflict requires reconciling changes, never guessing a newer version.
2. Establish the user's source, scope, grouping and required actions. The templates contain no production sample data. `?demo=1` enables labeled development fixtures only.
3. Read `ui/README.md` for the component catalog and dataset contract. Run `npm run library` to inspect real controls and the 12 compositions with labeled sample data. Reuse `ui/` components, shared Cobalt control classes, and inherited CSS theme variables. Do not replace the application shell. The dashboard renders inside it.
4. Discover data using `assistant_dashboards discover_sources` and `source_schema`. Declare `scriptFile` paths in `datasets.json`, author scripts under `datasets/`, and save exact authorized bindings in `source-bindings.json`. Keep credentials and provider calls out of browser code. Import the SDK from `@cobalt-code/dashboard`; it is an exact-version npm dependency in package.json and package-lock.json. The SDK uses the host bridge when published and its Vite plugin during development. Checkout provisions `.cobalt/connection.json`: a private, one-day server-side credential. Repeat checkout to renew it; never print or bundle it. Connected sources currently support reads only; local dashboard records support writes. Do not pretend an unsupported provider update worked.
5. Run `npm ci`, `npm test`, then `npm run dataset:test -- <key> --params '{}'` with actual parameters. Start `npm run dev`, register the normal task preview, and use Agent Browser to inspect responsive light/dark layouts and actual interactions with live data. The Vite plugin synchronizes the current dataset files before requests; fix sync errors instead of substituting fixtures. Do not supply dataset revisions. Run `npm run build` and `npm run preview` to test saved assets with the same scripts. Rebuild after source changes. Preview writes affect real dashboard records and require confirmation.
6. Run `npm run package`, then `dashboard_workspace` operation `import` with dashboardId and expectedVersion. The host reads the hash-verified package from this workspace. It saves source and compiled assets independently of the computer.
7. If publication was requested, activate the returned revision with `assistant_dashboards activate` and returned dashboard version. Verify real data/actions in the viewer. Report separately what passed in preview, build, and live data verification.

Do not publish `.env`, secrets, `.git`, node_modules, or a dev server URL. Assets must be bundled inline. The package command uses an explicit file allowlist and rejects symlinks. Source plus assets are bounded to 128 files / 8 million characters, with each file below 1 MiB. Dependencies must have a lockfile.
